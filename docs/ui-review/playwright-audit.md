## Implemented design requirements

### Overview

- KPI readout: total calls, resolution, correction, escalation, abandonment, and STT p90 latency.
- **Interruption rate vs. resolution result**: Recharts scatter plot, one point per observed call, with textual resolved/not-resolved labels and a representative evidence link.
- **Top intents by resolution rate**: Recharts horizontal bar chart with a text/link fallback for every displayed intent.
- **Top voice issues by impact**: Recharts horizontal bar chart showing percentage-point impact versus the observed comparison cohort. High interruption rate, slow STT finalization, and excessive dead air are all generated by the acceptance seed.
- Cost, usage, outcome provenance, voice behavior, recurring conditions, agent/provider comparisons, and cohort cards remain connected to the same filtered analytics response.

### Session detail

- **Conversation timeline** appears on every session detail view, independent of the active tab.
- Customer turns, agent turns, interruptions, and dead-air segments are visually distinct and also named in the legend, so color is not the only carrier of meaning.
- Timeline turn segments seek the recording; voice-event segments open normalized event evidence.
- Playback, Transcript, Analysis, and Trace & events tabs were individually exercised.
- Share now confirms `Copied`; re-analysis creates immutable queued runs; evidence links open their supporting turn/span/event.

### Intents and agents

- Replaced non-functional sidebar labels with real `/intents`, `/intents/:intent`, `/agents`, and `/agents/:agent` routes.
- List and detail screens show outcome coverage and link into canonical session evidence.
- Removed inactive Evaluations and Team entries because those advanced areas are outside the initial-release scope and should not appear as dead controls.

### Responsive and navigation behavior

- Desktop uses the persistent evidence-navigation sidebar.
- Tablet/mobile use one compact Menu control containing all available routes, profile settings, and sign-out.
- The previous narrow-screen header overflow is removed.
- Mobile intent tables and session tabs are contained without document-level horizontal overflow.
- Mobile controls receive at least a 44 px interaction height where dense desktop controls would otherwise be too small.
- A keyboard-visible skip link reaches the main routed content.

## Acceptance data

The final run used a fresh isolated SQLite database created from the current models, not a reused development database.

- 40 deterministic sessions
- 4 intents
- 3 agents and 3 agent versions
- resolved, failed, and escalated outcomes
- varied STT finalization latency
- interruptions, dead air, and transcript corrections
- recordings, turns, spans, usage, cost, errors, findings, and evidence links

The seed remains idempotent and all chart values come from persisted records. No chart uses hard-coded display values.

### Seed data versus production capture

Seed data is used only to make local acceptance deterministic and visually complete. The production data path is the same canonical schema and API:

- totals and outcome rates aggregate persisted sessions;
- intent comes from explicit session metadata and is promoted from a completed semantic analysis when the source did not provide it;
- interruption points count persisted `voice.interruption` events (emitted automatically by the LiveKit adapter when caller speech overlaps agent playback);
- STT p90 and slow-STT cohorts use persisted STT span duration, with event duration as a compatibility fallback;
- dead-air cohorts use explicit provider events or an observed turn gap above the same 2.5-second threshold used by deterministic response-gap analysis;
- correction rates count persisted `correction.*` events;
- playback, transcript, analysis, and event views read the selected session's persisted recording, turns, analysis runs/findings/evidence, spans, errors, and normalized events.

Missing source evidence stays `Unknown`, `Unclassified`, unavailable, or insufficient evidence. The UI does not substitute seed values into a real project.

The default session tab remains **Playback**, not Overview. The session header, metrics, and conversation timeline already form the overview and remain visible above every tab; calling the recording-specific tab Overview would hide its actual purpose. The four investigation tabs are therefore Playback, Transcript, Analysis, and Trace & events.
